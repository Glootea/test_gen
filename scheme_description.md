# Как подготовить банк заданий для генератора тестов

Этот файл объясняет, как устроены данные, из которых генератор собирает тесты. Данные записываются в формате JSON. Внешний объект содержит обязательный список `blocks` — блоков заданий.

## Общая структура

```json
{
  "blocks": [
    {
      "count": 2,
      "questions": [
        "Задание без дополнительных полей",
        {
          "q": "Текст вопроса",
          "a": "Правильный ответ",
          "l": "https://example.org/task"
        }
      ]
    }
  ]
}
```

В примере один блок. В нём указано, что нужно взять 2 задания из списка `questions`. 

## Блок заданий

У каждого блока должны быть два поля:

| Поле | Что указать |
|---|---|
| `count` | Сколько заданий нужно включить из этого блока. Целое число не меньше 1. |
| `questions` | Список доступных заданий.  |

Поле `images` можно добавить, если к заданиям блока относятся изображения.

## Описание задания

Элемент списка `questions` можно записать одним из двух способов:

1. **Простой текст** — строка с заданием.

Пример:
``` json
...: {
    "questions":
    [
        "Сколько будет 5*6?",
        "Сколько будет 7*8?"
    ]
}
...
```
2. **Объект** — запись с отдельными полями:

| Поле | Что указать |
|---|---|
| `q` | Текст вопроса. Для объекта это поле обязательно. |
| `a` | Ответ к вопросу. Необязательное поле. |
| `l` | Ссылка на задание. Необязательное поле. |

Пример:

```json
...: {
    "questions": [
        {
            "q": "Сколько будет 7 × 8?",
            "a": "56",
            "l": "https://example.org/multiplication"
        },
        {
            "q": "Сколько будет 5 x 6?",
            "a": "30"
        }
    ]
}
```


## Изображения

Поле `images` допускает два варианта: перечислить изображения или задать шаблон для серии изображений.

### Вариант 1. Перечень изображений

Укажите массив. Элементы могут быть путями или ссылками на изображения. Для элемента-объекта предусмотрены поля `i` (путь или пути к изображению) и `a` (ответ, связанный с изображением).

Пример со строками:
```json
"images": [
  "images/triangle.png",
  "images/circle.png",
]
```
Пример с объектами: 
```json
"images": [
  {
    "i": "images/square.png",
    "a": "Квадрат"
  },
  {
    "i": "images/circle.png",
    "a": "Circle"
  }
]
```
Пример с несколькими изображениями для одного вопроса:
```json
"images": [
  {
    "i": [
        "images/square.png",
        "images/circle.png"
    ],
    "a": "Квадрат и круг"
  },
]
```

### Вариант 2. Серия изображений по шаблону

Этот вариант удобен, когда задания отличаются только номерами в именах файлов. Замените меняющуюся часть имени на `%d`, перечислите шаблоны в `pattern` и задайте количество наборов в `imageCount`.

```json
"images": {
  "pattern": [
    "images/a-%d.png",
    "images/b-%d.png"
  ],
  "imageCount": 3,
  "relativeWidths": [0.4, 0.5],
  "answers": {
    "1": "Ответ для первого набора",
    "2": "Ответ для второго набора",
    "3": "Ответ для третьего набора"
  }
}
```

При таком примере получаются три набора: `a-1.png` вместе с `b-1.png`, затем файлы с номером 2 и файлы с номером 3.

| Поле | Что указать |
|---|---|
| `pattern` | Массив шаблонов путей. В каждом шаблоне `%d` заменяется номером. |
| `imageCount` | Сколько наборов создать. Целое число не меньше 1. |
| `relativeWidths` | Необязательный массив относительной ширины изображений в наборе. Например, `[0.4, 0.5]` задаёт соотношение ширины 4 к 5 (44% и 56% от ширины листа). Если сумарно значения превзойдут единицу, то изображения начнут переноситься на следующие строки. |
| `answers` | Необязательные ответы для изображений. Ключ — номер набора (`"1"`, `"2"` и т. д.), значение — ответ. |

Ответ в `answers` можно записать строкой или объектом с полем `a` для ответа и необязательным полем `l` для ссылки:

```json
"answers": {
  "1": {
    "a": "Ответ для первого набора",
    "l": "https://example.org/task/1"
  }
}
```
